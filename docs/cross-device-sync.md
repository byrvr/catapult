# Cross-Device Refresh Sync

Catapult needs more than Apple ID login to refresh an app from a different Mac.
Apple can tell us which App IDs and profiles exist, and a reachable device can
tell us what apps are installed, but neither Apple nor the device gives us the
original `.ipa` bytes needed for re-signing.

The reliable model is a Catapult-owned encrypted IPA vault plus a refresh
manifest that can be read from any Mac the user trusts.

## Goals

- A second Mac can sign in with the same Apple ID and recover previous Catapult
  installs.
- If the encrypted IPA exists remotely, the second Mac can download it, decrypt
  it, re-sign it, and refresh the app before expiry.
- Catapult never uploads Apple ID passwords, Apple auth tokens, signing private
  keys, or plaintext IPAs to a remote service.
- Missing device, missing IPA, expired auth, wrong team, and lock conflicts are
  explicit states instead of vague failures.

## Storage Model

Local durable state:

```text
~/.catapult/state.json
~/Library/Application Support/Catapult/IPAs/<sha256>.ipa
```

Remote state:

```text
teams/<team_id>/manifest.json.enc
teams/<team_id>/ipas/<sha256>.ipa.enc
```

The manifest contains only non-secret operational metadata:

- Apple ID and team ID
- device UDID, display name, and platform hints
- source bundle ID from the IPA
- installed bundle ID used on device
- extension bundle IDs
- IPA SHA-256, size, and original filename
- install time, expiry time, refresh-after time
- failure counters and last refresh status

The IPA blobs and manifest are encrypted before upload.

## Encryption

Catapult uses AES-GCM with a 256-bit sync key.

Key sources, in priority order:

1. `CATAPULT_SYNC_KEY` environment variable, shared by the user's Macs.
2. A local macOS Keychain key generated by Catapult.

The Keychain fallback is useful for a single Mac, but it is not enough for
cross-Mac recovery because another Mac cannot decrypt the remote vault. A future
UI should expose "Set Sync Recovery Key" and "Enter Recovery Key on This Mac" so
the same key can be installed safely on each trusted Mac.

## Providers

### Cloudflare R2

Recommended default for remote IPA blobs. R2 is S3-compatible, inexpensive for
large blobs, and does not charge normal public egress in the common path.

Configuration:

```bash
export CATAPULT_SYNC_PROVIDER=r2
export CATAPULT_SYNC_KEY=<shared recovery key>
export CATAPULT_R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
export CATAPULT_R2_BUCKET=catapult
export CATAPULT_R2_ACCESS_KEY_ID=...
export CATAPULT_R2_SECRET_ACCESS_KEY=...
```

### Sync Folder

Useful for iCloud Drive, Dropbox, Syncthing, or local testing.

```bash
export CATAPULT_SYNC_PROVIDER=folder
export CATAPULT_SYNC_KEY=<shared recovery key>
export CATAPULT_SYNC_FOLDER="$HOME/Library/Mobile Documents/com~apple~CloudDocs/Catapult"
```

When Catapult is launched from Finder, shell exports are usually not inherited.
Use `~/.catapult/config.env` for persistent local configuration:

```text
CATAPULT_SYNC_PROVIDER=folder
CATAPULT_SYNC_KEY=<shared recovery key>
CATAPULT_SYNC_FOLDER=/Users/you/Library/Mobile Documents/com~apple~CloudDocs/Catapult
```

### Supabase

Supabase is still useful for a future hosted product because it provides auth,
Postgres, row-level security, and admin tooling. It should not be the only IPA
blob store for the free-tier product because IPA storage and egress can grow
quickly. The clean production shape is:

- R2 for encrypted blobs.
- Supabase for indexed metadata, devices, refresh leases, and user/team mapping.

The current implementation keeps metadata in the encrypted manifest so it works
without a hosted database.

## Sync Flow

On upload:

1. Validate the IPA.
2. Copy it into the local content-addressed vault.
3. If sync is configured and authenticated, upload encrypted IPA blob.

On install:

1. Install from the durable vault path.
2. Record install metadata with IPA SHA-256.
3. Merge local state with the remote manifest.
4. Upload missing encrypted IPA blobs.
5. Push the encrypted manifest.

Remote IPA blobs are content-addressed by SHA-256. Catapult checks for an
existing encrypted blob before uploading, so normal sync runs do not re-upload
large IPAs that are already present.

If `CATAPULT_SYNC_PROVIDER` is configured but `CATAPULT_SYNC_KEY` is missing,
sync stops with a `needs_key` status instead of creating a local-only remote
vault. If the key cannot decrypt an existing remote manifest, sync reports
`wrong_key`.

On login from a different Mac:

1. Restore Apple ID session and fetch team ID.
2. Pull and decrypt the remote manifest.
3. Download any missing encrypted IPA blobs.
4. Merge remote install records into local state.
5. Account view shows recovered records as ready, missing IPA, device offline,
   or wrong account/team.

## Locking

Remote refresh should eventually use short leases:

```json
{
  "locked_by": "machine-id",
  "locked_until": 1780000000.0,
  "operation": "refresh"
}
```

This prevents two Macs from refreshing the same app simultaneously. The first
implementation focuses on vault and manifest sync; leases should be added before
running unattended refresh from multiple Macs at once.
